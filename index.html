Proxmox · Wazuh · ELK · NSM

Segmented Homelab SOC Architecture

A working security operations lab. A dedicated InfoSec Proxmox host runs the SIEM, network sensors, vulnerable targets, an air-gapped malware sandbox, and a GPU-accelerated Frigate NVR for the house cameras, each on its own firewalled VLAN. Attacks from Kali are detected by both host agents and a mirrored-traffic sensor, then escalated to my ops dashboard on the homelab host.

Hypervisor: Proxmox VE SOC VLANs 2 · 4 · 5 · 6 · 74 Zone firewall Sensor: Proxmox tc mirror NVR GPU passthrough

Detection engineering

Wazuh host telemetry correlated with Zeek, Suricata, and Snort in ELK. 9 custom Wazuh rules mapped to MITRE ATT&CK.

Vulnerability management

Authenticated OpenVAS and OWASP ZAP scans, DefectDojo tracking, and 6 documented remediation change records.

Malware analysis

REMnux and FlareVM on a no-route VLAN with simulated internet (INetSim) on REMnux.

Project overview

Skills demonstrated

Everything on this page is deployed and in use. The lab follows enterprise patterns: the SIEM and analytics live on an isolated services VLAN, attack and target networks are separated, network traffic is mirrored to a passive sensor, and malware never touches a routed network. The underlying network and hardware are on the network & hardware page, and the second Proxmox host is on the homelab services page.

Detection architecture

Host + network correlation

How the sensor sees traffic

The targets are VMs on the same Proxmox host as the sensor, so a switch mirror port could not see their traffic. Instead, a Linux tc mirror on the host's physical uplink copies VLAN traffic to a dedicated capture interface on the sensor VM. A systemd unit and a VM hook script re-apply the mirror after reboots.

Known blind spot: SSH between two VMs on the Targets VLAN stays inside the Proxmox bridge and never reaches the mirror. Lateral movement is detected by the Wazuh agents instead.

Network detection → ELK

Zeek · Suricata · Snort

Zeek writes connection, HTTP, and SSH metadata; Suricata and Snort (JSON alerts) add signature hits. Filebeat ships all three to Logstash, and Kibana holds the baseline and investigation dashboards.

Host detection → Wazuh

Agents, auditd, custom rules

Agents on DVWA and Metasploitable forward auth, web, and auditd logs. Custom rules (100010–100021) cover SQL injection, command injection, web-shell upload, Nmap scans, HTTP error bursts, and PwnKit.

Camera NVR · VLAN 74

GPU detection on the InfoSec host

The house cameras are battery-powered Wi-Fi cameras with no native video stream and no hardware NVR, so a VM on the InfoSec Proxmox host is the NVR. A low-profile NVIDIA GPU in that host is passed through to the VM with VFIO. Frigate's TensorRT build runs a lightweight YOLO detector on the GPU with hardware video decode, tracks people, and runs face recognition. Snapshots are kept; continuous recording is off.

→ Camera event pipeline

Wi-Fi cameras (dedicated SSID)→ Protocol bridge → RTSP→ go2rtc restream→ Frigate · GPU detection · faces · attributes→ MQTT event→ Forwarder on the AI box → Dot speaks

Dot does not analyze video. Frigate does detection; a forwarder service on the AI box turns MQTT events into spoken alerts (a known person by name, or “An unauthorized person was detected.”). Dot itself is documented on the homelab page.

Access

Behind Traefik + Authentik

The Frigate UI and the go2rtc live tiles are served by Traefik on the homelab host with Authentik in front. The ops dashboard shows the live tiles, and phones reach the NVR over WireGuard.

Isolation

Cameras never leave VLAN 74

Cameras are denied the internet and every other private network. Only the protocol bridge on the NVR VM talks to them. Inbound, the lab gateway allows Traefik to the UI, the AI box to MQTT, and trusted/VPN clients to the UI and WebRTC.

Operational data flows

How components integrate

1 Attack traffic → network detection

Kali (VLAN 6)→ DVWA / Metasploitable→ tc mirror → NSM sensor→ Zeek · Suricata · Snort→ Filebeat → Logstash→ Elasticsearch · Kibana

The lab gateway allows Attack → Targets; the sensor is passive and only receives a copy of the traffic.

2 Host telemetry → Wazuh

Target agents + auditd→ Wazuh manager→ Custom rules + MITRE IDs→ Wazuh dashboard

Targets may reach Sec Services only on the agent ports, so a compromised target cannot reach the SIEM's admin interfaces.

3 Alert escalation out of the SOC

Wazuh integration (level ≥ 7)→ Ops dashboard webhook→ Alert inbox + ntfy push→ Dot AI (homelab) speaks “high” alerts

A custom Wazuh integration script posts each alert with a shared secret; clicking an alert in the dashboard opens the exact Wazuh document.

4 Vulnerability management lifecycle

OpenVAS (authenticated)+ OWASP ZAP (DVWA)→ DefectDojo triage→ Fix on target→ Change record + rescan

Before/after OpenVAS and ZAP reports document each remediation, from ProFTPD mod_copy to PwnKit.

5 Isolated malware analysis

Admin PC (Mgmt)→ Break-glass copy to REMnux→ Static analysis→ FlareVM detonation + INetSim→ IOC report (no binaries out)

The lab gateway drops Malware → WAN and Malware → every VLAN. FlareVM's DNS and gateway point at REMnux, so all “internet” is simulated.

6 Person at the door → spoken alert

Camera wakes on motion→ Frigate person + face match→ MQTT event→ Forwarder (VLAN 3)→ Dot speaks on Lab Dash

The forwarder waits a few seconds for a face match before announcing a stranger, so known people are called by name instead of “unauthorized”.
