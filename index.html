Segmented Homelab SOC Architecture

A production-style cybersecurity laboratory on real UniFi hardware: the Fiber Cloud Gateway protects the home, while a dedicated UDR7 gateway owns server VLANs and firewall policy — offloading lab inspection from the edge. Proxmox hosts the SOC, NSM, and on-premises security AI stack.

Physical network topology

As built

AT&T Fiber hands a public IP to the UniFi Fiber Cloud Gateway via IP passthrough. Personal systems live on the 10G UniFi switch. The UDR7 is a dedicated lab gateway so inter-VLAN firewall and Threat Management for servers do not consume Cloud Gateway CPU.

Logical lab architecture

Gateway roles
Site: Home

UniFi Fiber Cloud Gateway

Internet edge after AT&T passthrough. Firewalls personal systems on the 10G switch, provides home Wi‑Fi/VPN as configured, and exposes a dedicated Lab-Uplink network to the UDR7. Keeps heavy lab east–west inspection off this CPU.

Site: Lab

UniFi UDR7

Dedicated server/lab gateway. Owns lab VLANs, inter-VLAN firewall rules, and optional UniFi Threat Management for the 2.5G segment. Trunks VLANs to Proxmox and the second homelab server. Managed as a separate UniFi site to avoid dual-gateway conflicts.

Detection stack roles

UDR7 — lab VLAN routing and firewall policy. Wazuh — host/endpoint SIEM (agents, FIM, Sysmon). ELK — network analytics for Zeek logs and Suricata/Snort alerts. Zeek — protocol metadata. Suricata & Snort — signature IDS on the SPAN sensor (comparative analysis).

Operational data flows

How components integrate

0 Path to the lab

AT&T Fiber→ Cloud Gateway→ 10G Switch→ UDR7 Lab GW→ 2.5G Switch→ Proxmox / servers

Personal traffic stays on the Cloud Gateway path. Only lab-destined traffic crosses the UDR7 uplink.

1 Home security AI pipeline

Reolink cameras→ Frigate→ Mosquitto→ Custom face AI→ Piper TTS + event log

Remote access via UniFi VPN on the Cloud Gateway (and/or lab site), then routed to VLAN 30. No public ports.

2 Network security monitoring → ELK

Attack ↔ Targets→ SPAN→ Zeek · Suricata · Snort→ Logstash→ Elasticsearch · Kibana

East–west lab traffic is firewalled on the UDR7 and observed by the NSM sensor — not inspected packet-by-packet on the Cloud Gateway.

3 Host SIEM (Wazuh) with NSM correlation

Endpoint agents→ Wazuh Manager→ Wazuh Dashboard
Suricata / Snort alerts→ syslog → Wazuh+ ELK (full retention)

Join host auth/FIM/Sysmon with network IDS hits for a single investigation narrative.

4 Vulnerability management lifecycle

OpenVAS→ VLAN 40→ DefectDojo→ Remediation report

CVSS triage, risk acceptance, and formal reporting suitable for GRC / vulnerability analyst portfolios.

5 LLM-assisted alert triage

Wazuh / Kibana JSON→ Ollama (GPU)→ Triage UI→ Ticket draft

Severity classification, investigation suggestions, and draft tickets — AI applied to SecOps workflow.

6 Isolated malware analysis

Sample→ FlareVM / REMnux→ INetSim→ IOC / threat report

UDR7 firewall denies Malware VLAN egress. Reports exported manually through Management after analysis.

Inter-VLAN trust model

Enforced on UDR7

Firewall policy on the UDR7 implements least privilege between lab zones. The Cloud Gateway only needs allow/deny for the lab uplink and any static routes into lab subnets from the Home site.

From \ To 10 Mgmt 20 Services 30 AI 40 Targets 50 Malware 60 Attack
10 Mgmt Allow Allow Allow Allow Break-glass Allow
20 Services Deny Allow Events in Scan only Deny Deny
30 AI / HomeSec Deny Syslog Allow Deny Deny Deny
40 Targets Deny Agent → Wazuh Deny Allow Deny Deny
50 Malware Deny Deny Deny Deny Allow Deny
60 Attack Deny Optional syslog Deny Allow Deny Allow

Allow = permitted · Limited = specific ports/protocols · Deny = default drop. Malware VLAN has no default route.
