Homelab Services Architecture

A dedicated “for fun” compute host for media, game servers, a fleet dashboard, and utility services — sitting on the same UniFi lab fabric as the InfoSec stack, but isolated so entertainment workloads never share fate with the SOC.

Game servers

Containerized or VM-backed multiplayer hosts with controlled ports and friends-only access.

Fleet visibility

One dashboard for uptime, container health, and links into both this host and the SOC.

Where this host sits

Same fabric, separate role

AT&T → Cloud Gateway → 10G core still owns personal clients. The UDR7 owns the 2.5G lab switch. The InfoSec Proxmox box runs SOC/NSM/AI; this Homelab Server runs leisure and utility containers on a services-oriented VLAN (demo: VLAN 70).

Design intent

Blast-radius control: a noisy game update or media transcode should not starve Wazuh/ELK. Clear story for employers: you operate both a security lab and a production-minded self-hosted platform on one documented topology.

Operational flows

How day-to-day use works

1 Watch something at home

Trusted client→ Cloud Gateway / LAN→ UDR7→ Jellyfin

Internal hostname via reverse proxy. No WAN publish of the media stack.

2 Friends join a game server

Friend client→ VPN or allowed UDP/TCP→ UDR7 DNAT / firewall→ Game container

Prefer VPN invite links. If a port must be open, scope it to that service only and monitor with Uptime Kuma + UniFi logs.

3 Fleet dashboard

Exporters→ Prometheus→ Grafana
Uptime Kuma→ Homepage widgets+ Optional SOC UI links

One place to open Jellyfin, game panels, Grafana, and deep-links into Wazuh/Kibana when on VPN.

4 Backup discipline

Compose + configs→ Restic / Borg→ Local + offsite target

Media blobs may be large; prioritize configs, databases, Immich metadata, and game world saves.
